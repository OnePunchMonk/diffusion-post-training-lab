# Model leaderboard

Every checkpoint pushed to the Hub gets a row here, generated by
`scripts/update_models_md.py` from its eval report — this file is a build
artifact, not something to hand-edit (aside from the "Notes" column).

**CLIP-T** is prompt fidelity, **DINO** and **CLIP-I** are subject fidelity
against the training references. Higher is better for all three, but CLIP-T
and DINO pull in opposite directions — an adapter that learned nothing scores
well on the first, one that memorized its training shots scores well on the
second, so they are only meaningful read together.

The klein rows are scored on **held-out** recontextualization prompts, not on
SynCD's own prompts (which generated the training images). They are **n = 1
subject**: a pipeline-validation run, not a benchmark. See
[`flux2-klein-peft/RESULTS.md`](flux2-klein-peft/RESULTS.md) for both splits,
the memorization gap between them, and five confounds.

## How a row gets here

```bash
# 1. train
accelerate launch scripts/train.py --config configs/recipes/dpo.yaml

# 2. benchmark
dptlab eval --checkpoint outputs/dpo-sdxl/final --baseline-model-key sdxl \
    --prompts prompts/geneval_mini.jsonl --output-dir eval_results/dpo-sdxl

# 3. publish
python scripts/push_to_hub.py --checkpoint outputs/dpo-sdxl/final \
    --repo-id OnePunchMonk/dptlab-sdxl-dpo-v1 \
    --eval-report eval_results/dpo-sdxl/report.json

# 4. record the row
python scripts/update_models_md.py --repo-id OnePunchMonk/dptlab-sdxl-dpo-v1 \
    --checkpoint outputs/dpo-sdxl/final --eval-report eval_results/dpo-sdxl/report.json
```
